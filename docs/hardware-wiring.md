# 4WD 주행 로봇 하드웨어 배선

이 문서는 다음 하드웨어의 기준 핀과 배선 구조를 정의한다.

- ESP32 DevKitC V4, ESP32-WROOM-32D, CP2102
- L9110S Dual H-Bridge 모터 드라이버 2개
- DC 모터 4개
- A/B상 주행 엔코더 4개(각 바퀴당 1개)
- MPU6050 모듈 1개

각 L9110S 모듈은 한 축의 모터 2개를 담당한다. Driver #1은 전륜 좌우
모터를, Driver #2는 후륜 좌우 모터를 구동하며, 네 모터는 각각 독립된
H-브리지 채널과 PWM 출력을 사용한다. 상위 주행 제어에서는 네 독립 채널을
좌우 속도로 묶어 skid-steer 명령을 수행할 수 있다. 모터 핀은 펌웨어
기본값과 일치한다.

## ESP32 핀 사용 원칙

| 구분 | GPIO | 사용 원칙 |
|---|---|---|
| SPI Flash | 6~11 | 연결하지 않는다 |
| CP2102 UART | 1, 3 | 펌웨어 다운로드와 micro-ROS USB-UART 통신에 사용한다 |
| 부팅 스트래핑 | 0, 2, 5, 12, 15 | 외부 회로가 부팅 레벨을 바꿀 수 있으므로 사용하지 않는다 |
| 입력 전용 | 34, 35, 36, 39 | 센서 입력에만 사용하며, 내부 풀업/풀다운이 없다 |
| 기본 I2C | 21, 22 | MPU6050 SDA/SCL에 사용한다 |

GPIO16과 GPIO17은 ESP32-WROOM-32D가 장착된 DevKitC V4에서는 사용할 수
있다. ESP32-WROVER 계열 보드로 변경할 경우 내부 메모리 연결 여부를 다시
확인해야 한다.

## 전체 GPIO 할당

| 기능 | 신호 | ESP32 GPIO |
|---|---|---:|
| 좌측 전륜 모터 | FL IA / IB | 25 / 26 |
| 우측 전륜 모터 | FR IA / IB | 27 / 14 |
| 좌측 후륜 모터 | RL IA / IB | 19 / 18 |
| 우측 후륜 모터 | RR IA / IB | 17 / 16 |
| 좌측 전륜 엔코더 | FL A / B | 32 / 33 |
| 우측 전륜 엔코더 | FR A / B | 34 / 35 |
| 좌측 후륜 엔코더 | RL A / B | 36 / 39 |
| 우측 후륜 엔코더 | RR A / B | 23 / 13 |
| MPU6050 | SDA / SCL | 21 / 22 |

GPIO 설정 항목과 유효 범위는 `components/board/Kconfig`에서 정의하고, 이
차량에서 사용할 기본값은 다음 파일에서 관리한다.

- `sdkconfig.defaults`
- `components/motor/test_apps/hardware/sdkconfig.defaults`

이미 생성된 `sdkconfig`가 있으면 그 설정이 기본값보다 우선할 수 있다.
핀을 변경할 때는 문서와 설정 파일을 함께 변경한다. 네 엔코더는 각각 독립된
PCNT quadrature 카운터를 사용하고, MPU6050은 I2C 드라이버가 이 핀을
사용한다.

## L9110S 모터 드라이버

L9110S 모듈에 따라 입력 핀이 `A-IA/A-IB/B-IA/B-IB` 또는
`A1A/A1B/B1A/B1B`로 표기될 수 있다.

### Driver #1: 전륜 모터, J2 헤더

| L9110S 단자 | 연결 |
|---|---|
| A-IA | GPIO25, J2-9 |
| A-IB | GPIO26, J2-10 |
| Motor A 출력 | 좌측 전륜 모터 |
| B-IA | GPIO27, J2-11 |
| B-IB | GPIO14, J2-12 |
| Motor B 출력 | 우측 전륜 모터 |
| VCC | 모터 정격 전압 전원 |
| GND | 공통 GND |

전륜 드라이버의 제어선 4개는 DevKitC J2 헤더의 9~12번 핀에 연속으로
배치된다.

### Driver #2: 후륜 모터, J3 헤더

| L9110S 단자 | 연결 |
|---|---|
| A-IA | GPIO19, J3-8 |
| A-IB | GPIO18, J3-9 |
| Motor A 출력 | 좌측 후륜 모터 |
| B-IA | GPIO17, J3-11 |
| B-IB | GPIO16, J3-12 |
| Motor B 출력 | 우측 후륜 모터 |
| VCC | 모터 정격 전압 전원 |
| GND | 공통 GND |

후륜 드라이버의 제어선은 J3 헤더 8, 9, 11, 12번 핀에 배치된다. 그 사이의
J3-10(GPIO5)은 부팅 스트래핑 핀이므로 연결하지 않는다.

각 IA/IB 입력과 GND 사이에 10 kΩ 풀다운 저항을 추가한다. 이 저항은 ESP32
리셋 및 부트로더 실행 중 입력이 떠서 모터가 순간적으로 움직이는 것을
방지한다.

### 제어 논리

| IA | IB | 동작 |
|---:|---:|---|
| 0 | 0 | 정지/브레이크 |
| PWM | 0 | 한 방향 속도 제어 |
| 0 | PWM | 반대 방향 속도 제어 |
| 1 | 1 | 정지/브레이크 |

실제 전진 방향은 모터 단자 배치에 따라 바뀔 수 있다. 배선을 바꾸기 전에
`menuconfig`의 해당 `MOTOR_*_INVERTED` 옵션으로 방향을 보정할 수 있다.

현재 펌웨어는 0을 거쳐 방향을 전환하고 IA와 IB에 동시에 구동 PWM을
출력하지 않도록 구현되어 있다. 같은 방향에서 PWM 듀티만 변경할 때는
출력을 0으로 만들지 않고 활성 H-브리지 입력의 듀티를 연속 갱신한다.

### 모터 PWM

네 모터는 같은 속도 명령에 동일한 PWM 듀티를 사용한다. 공개 퍼센트 API의
하드웨어 시험 명령 60은 60%에 해당한다. 내부 정규화 명령에서 기동 부스트
800은 80%, 최대 명령 1000은 100%에 해당한다. 하드웨어 시험 메뉴의 3초
완전 출력 시험은 퍼센트 명령 100을 사용하므로 활성 H-브리지 입력이 계속
HIGH로 유지되고 PWM 스위칭이 발생하지 않는다.

### 기동 부스트

정지 상태에서 800 미만의 주행 명령이 들어오거나 저속으로 회전 방향이
바뀌면, 펌웨어는 800 명령을 100 ms 동안 적용한 뒤 요청된 값으로
복귀한다. 네 바퀴를 함께 구동할 때는 네 채널에 동일한 80% 부스트를 먼저
설정하고 한 번만 100 ms를 기다린다. 부스트에서 지속 PWM으로 내려갈 때는
같은 방향의 출력이므로 0을 거치지 않고 듀티만 변경한다.

- `CONFIG_MOTOR_START_BOOST_SPEED=800`: 부스트 명령 크기
- `CONFIG_MOTOR_START_BOOST_DURATION_MS=100`: 부스트 유지 시간

부스트를 사용하지 않으려면 `CONFIG_MOTOR_START_BOOST_SPEED=0`으로
설정한다. 부스트 구간에는 평상시보다 큰 전류가 흐를 수 있으므로 첫 시험은
바퀴를 띄운 상태에서 수행하고 L9110S 및 모터의 온도와 전원 전압 강하를
확인한다.

## 엔코더

네 바퀴에 A/B상 quadrature 엔코더를 하나씩 설치한다. 각 엔코더를 해당
모터와 같은 FL(좌측 전륜), FR(우측 전륜), RL(좌측 후륜), RR(우측 후륜)
이름으로 관리하면 배선 점검과 방향 보정 시 혼동을 줄일 수 있다.

| 엔코더 | A상 | B상 | 전원 | GND |
|---|---|---|---|---|
| FL | GPIO32, J2-7 | GPIO33, J2-8 | 3V3 또는 엔코더 정격전압 | 공통 GND |
| FR | GPIO34, J2-5 | GPIO35, J2-6 | 3V3 또는 엔코더 정격전압 | 공통 GND |
| RL | GPIO36, J2-3 | GPIO39, J2-4 | 3V3 또는 엔코더 정격전압 | 공통 GND |
| RR | GPIO23, J3-2 | GPIO13, J3-17 | 3V3 또는 엔코더 정격전압 | 공통 GND |

GPIO36과 GPIO39는 센서 입력 전용 핀이므로 RL 엔코더에 배정한다. GPIO23과
GPIO13은 이 구성에서 남는 일반 GPIO이며 RR 엔코더 입력으로 사용한다.
스트래핑 핀, SPI Flash 핀, UART 및 I2C 핀은 엔코더에 사용하지 않는다.

배선 조건:

- 3.3 V 푸시풀 출력은 ESP32에 직접 연결할 수 있다.
- 오픈 컬렉터 출력은 각 A/B 신호를 4.7~10 kΩ 저항으로 3.3 V에
  풀업한다.
- GPIO34, GPIO35, GPIO36, GPIO39에는 ESP32 내부 풀업/풀다운이 없으므로
  FR 및 RL 엔코더에는 출력 형식에 맞는 외부 바이어스가 반드시 필요하다.
- 5 V 푸시풀 출력은 ESP32에 직접 연결하지 않는다. 3.3 V 레벨 시프터를
  사용한다.
- 모터선과 엔코더선을 떨어뜨리고, 가능하면 각 신호를 GND와 꼬아 배선한다.
- 네 엔코더의 A/B 신호선 8개는 서로 묶지 않고 ESP32에 개별 연결한다.
- 펌웨어에서는 엔코더별로 독립된 ESP32 PCNT 하드웨어 카운터를 사용한다.
- 커넥터와 케이블 양쪽에 FL/FR/RL/RR을 표시하고, 신호선 순서는 모든
  엔코더에서 VCC-GND-A-B처럼 동일하게 맞춘다.

각 바퀴의 count와 RPM을 개별 측정하면 같은 쪽 앞뒤 바퀴의 속도 차이,
공회전, 끌림 및 한 바퀴의 stall을 구분할 수 있다. skid-steer odometry에는
좌측 FL/RL의 평균과 우측 FR/RR의 평균을 사용한다. 현재 펌웨어도 같은
쪽의 두 RPM 평균을 좌우 PID 피드백으로 사용하며, 네 모터를 완전히 독립된
PID로 제어하려면 모터 출력 인터페이스와 주행 제어기를 추가로 확장해야 한다.

### 펌웨어 반영 사항

현재 저장소의 `wheel_encoder` 인터페이스와 보드 설정은 FL/FR/RL/RR
4채널을 정의한다. 주행 제어는 좌측 FL/RL RPM 평균과 우측 FR/RR RPM
평균을 기존 좌우 PID 및 odometry 입력으로 사용한다. stall 판정은 네
엔코더를 개별 감시하므로 바퀴 하나라도 목표 속도에서 움직이지 않으면
모터 출력을 정지한다.

ROS `/joint_states`는 기존 호환성을 위해 좌·우 두 joint를 유지하며 각
위치와 속도에는 같은 쪽 전·후륜의 평균값을 게시한다.

## MPU6050

일반적인 GY-521 모듈 기준 연결이다.

| MPU6050 단자 | 연결 |
|---|---|
| VCC | ESP32 3V3 |
| GND | 공통 GND |
| SDA | GPIO21, J3-6 |
| SCL | GPIO22, J3-3 |
| AD0 | GND, I2C 주소 `0x68` |
| XDA/XCL | 연결하지 않음 |

SDA와 SCL 풀업이 모듈에 없다면 각각 4.7 kΩ 저항으로 3.3 V에 풀업한다.
현재 펌웨어는 polling으로 측정하며 INT 핀은 사용하지 않는다. 시작할 때
`WHO_AM_I`를 확인하고 통신 복구 시 I2C bus를 reset한 뒤 장치를 다시
설정한다.

MPU6050을 차체 중심에 가깝게, PCB 축이 차체 축과 나란하도록 단단히
고정한다. 모터 전원선 및 모터 자석과 거리를 두고 설치한다.

MPU6050 IC의 VDD 허용 범위는 2.375~3.46 V이다. 5 V 입력을 허용한다고
표시된 GY-521 모듈도 있지만 모듈 복제품의 회로가 서로 다를 수 있으므로
이 설계에서는 3.3 V를 사용한다.

## 전원 구조

```text
배터리 +
   |
   +-- 퓨즈 -- 비상 정지/전원 스위치 -- 모터 정격 전압 버스
   |                                      +-- L9110S #1 VCC
   |                                      +-- L9110S #2 VCC
   |
   +-- 5 V Buck Converter -------------------- ESP32 5V
                                                |
                                                +-- ESP32 3V3
                                                    +-- MPU6050
                                                    +-- 3.3 V 엔코더 4개

배터리 -, Buck GND, ESP32 GND, L9110S GND,
MPU6050 GND 및 엔코더 GND는 모두 공통으로 연결한다.
```

전원 설계 조건:

- 모터를 ESP32의 5V 또는 3V3 핀에서 공급하지 않는다.
- USB와 외부 5V 핀으로 ESP32에 동시에 전원을 공급하지 않는다. 개발 중
  USB를 연결해야 한다면 외부 5V를 분리하거나 적절한 power ORing 회로를
  사용한다.
- Raspberry Pi 5 USB로 ESP32에 전원을 공급하는 구성에서는 해당 USB
  케이블이 CP2102 통신도 담당한다. 모터 전원은 별도 공급하고 GND만
  공통으로 연결한다.
- 각 L9110S 모듈 가까이에 470~1000 µF 전해 콘덴서와 100 nF 세라믹
  콘덴서를 VCC-GND 사이에 배치한다.
- 각 모터 단자 가까이에 100 nF 세라믹 콘덴서를 배치한다.
- 모터 전류가 흐르는 경로와 센서 GND 경로를 분리한 뒤 전원 입력 근처에서
  합치는 스타 접지를 권장한다.
- 배터리, 배선, 커넥터, 스위치 및 퓨즈는 네 모터의 합산 정지 전류를
  기준으로 선정한다.

L9110S는 일반적으로 2.5~12 V, 채널당 약 800 mA급 소형 모터용이다. 모터의
정지 전류가 이 범위를 넘으면 더 높은 전류 정격의 드라이버를 사용한다.

## 최초 구동 점검

1. 모터 전원을 연결하지 않은 상태에서 ESP32가 정상 부팅되고 MPU6050의
   I2C 주소 `0x68`이 검색되는지 확인한다.
2. 바퀴를 하나씩 손으로 돌려 FL, FR, RL, RR 엔코더의 A/B 카운트가 서로
   독립적으로 변하는지 확인한다.
3. 네 바퀴를 전진 방향으로 돌렸을 때 모든 count가 양수가 되도록 엔코더별
   방향 반전 설정을 조정한다.
4. 로봇의 바퀴가 지면에 닿지 않도록 차체를 고정한다.
5. 모터 전원을 연결하고 각 모터를 낮은 듀티로 하나씩 시험하여 해당
   바퀴의 엔코더만 변하는지 확인한다.
6. 좌우 전진 방향이 맞지 않으면 모터 극성 또는 펌웨어의 `INVERTED`
   설정을 수정한다.
7. 전체 전진, 후진 및 제자리 회전을 시험한 뒤 비상 정지가 정상 동작하는지
   확인한다.
8. 바퀴를 띄운 상태에서 전체 4륜 12초 연속 전진 시험을 실행한다. 이어서
   전륜만, 후륜만 구동하는 부하 시험 메뉴에서 25%, 50%, 75%, 100%를
   각각 선택하고 해당 출력이 12초씩 유지되는지 확인한다.
9. 필요하면 3초 완전 출력 시험을 실행하고 네 모터가 끝까지 유지되는지
   확인한다.
10. 지속 시험 중 L9110S 온도와 배터리 전압 강하를 점검하고 축별 차이를
   비교한다.
11. 전륜과 후륜의 최소 기동 출력 시험을 각각 실행한다. 시험은 정지
    상태에서 5%부터 100%까지 5%씩 올리므로, 양쪽 바퀴가 처음 함께
    회전하는 출력값을 로그에서 기록한다.
12. 전륜과 후륜의 최소 유지 출력 시험을 각각 실행한다. 시험은 100%에서
    기동한 뒤 5%까지 5%씩 내리므로, 양쪽 바퀴가 계속 회전하는 마지막
    출력값을 기록한다. 각 출력은 2초 동안 유지된다.

하드웨어 모터 시험 절차는 프로젝트 루트 `README.md`의
`Motor Hardware Test` 절을 따른다.
